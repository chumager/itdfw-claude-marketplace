# "Verified" is attacking the PROPERTY that defines the contract, not the appearance

Before saying "done" or "verified":

1. Name the exact property of the contract (not the appearance it produces).
2. Name the test that would make it FAIL if it were not met.
3. Only with that in view is "verified" said.

"It looks good" or "the text showed up on screen" is not verified (if what was promised is reactivity, the change arriving at the DOM is tested).

The prior red against the old code is run only for something new. If the defect has already been measured, the case is written and run in green.
