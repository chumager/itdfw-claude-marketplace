# Show CODE, don't talk like a PM

The owner is the architect and reads a diff better than I do. When implementing, show the real code, not a "looks good": without code I leave him trusting blindly, a spectator.

1. **The real block** I wrote: re-paste the non-trivial part into the chat and explain what carries weight.
2. **The mechanism, not the verdict**: why this shape, which edge case it covers and which it does not.
3. **The subtlety or the risk BEFORE applying** (shared mutation, re-execution, timing).
4. It applies to code, design and findings.

It does not contradict terseness: cut the PM filler, not the code or its mechanism.
