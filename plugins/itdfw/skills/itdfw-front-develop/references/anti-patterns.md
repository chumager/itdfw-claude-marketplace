# Anti-Patterns

| WRONG | RIGHT | Why |
|-------|-------|-----|
| Write full renderInput JSX | Set `tag` in data + `getInputProps()` | GI's renderMainInput handles tag, ref, events |
| `getInputProps()` returns new object | `{...this.defaultGetInputProps(), extras}` | Without spread: breaks state, value, disabled |
| `CoreX.methods.renderInput.call(this)` | `this.defaultRenderInput()` | Inherited methods not in literal object |
| `this[this.$options.$validateSelfValue]` | `this.validateSelfValue` | Computed has getter+setter. Verbose form ONLY in `data()` to create the reactive property |
| Manual value watchers | Let validateSelf handle it | VS watcher validates + emits automatically |
| `validate: {required}` on outer composite | Put required on inner form fields | Outer validates via type validator |
| `import X from "./X.jsx"` for component with loaders | `localImport("X", "base")` | Direct import bypasses addLoader pipeline |
| Missing or generic `name` in component | `name: "ItdMyComponent"` (unique) | GI warns in dev; Vue devtools useless without proper name |
| Creating front file that only extends core | Don't create it | Noop front = waste. Cascade finds core directly. Front only exists if it ADDS something |
| `import GenericInput from "./GenericInput.jsx"` in core | `/*global GenericInput*/` | Direct import = raw without loaders. No validateSelf, no $lodash, nothing |
| Front extends core when UI paradigm differs completely | Extend GI directly | Cascade core→front is a *should*, not a *must*. If front resets everything from core (e.g., Boolean: core=checkbox, front=ToggleButton), extending core adds a useless layer |
| `{this.validateSelfValue}` in custom renderInput JSX | `{this.initVal(this.resolvedValue)}` | Internal state in render = circular reactivity (self re-render). Parent prop in render = linear flow (reactive to external only) |
| Moving value to `mounted()` to avoid reactivity | Keep `initVal(resolvedValue)` in render | Kills reactivity to parent. Component must stay reactive to external changes |
| `formBus.on()` without `formBus.off()` in unbind/destroy | Always cleanup: `off()` in `unbind`/`beforeDestroy` | Silent memory leak. formBus lives on the form — listeners hold references to destroyed components. 8h session without refresh = accumulated dead forms the GC can't collect |
| `initVal` that reads `this.dateType` (computed/data from child) | Set `[this.$options.$validateSelfValue]: initial` in child's `data()` | **DEADLOCK**: GI's `data()` calls `initVal()` BEFORE child's `data()`/computed exist. Fix: compute initial value manually in child's `data()` using raw props (`this.input?.dateType`), then override `$validateSelfValue` |
| `<ButtonTag on={{click: handler}}>` sin `type="button"` | `<ButtonTag type="button" on={{click: handler}}>` | **FORM SUBMIT**: `<button>` nativo defaults a `type="submit"` (spec HTML). Dentro de un form, click dispara submit → validación cascada en TODOS los inputs. BButton de BV pone `type="button"` internamente, pero ButtonTag resuelve a `<button>` nativo en core. Síntoma: click en un botón de un input gatilla validadores de otros inputs (ej: password toggle ejecuta TimeFrame validator) |
| GI wrapping GF (`extends GI` + `tag: GF`) | `extends GenericFormCore` directly | **GF IS A GI**. GF hereda todo el pipeline de GI (initVal, emitter, validateSelf, render). Wrapping = capa extra inútil: más render cycles, más watchers, más complejidad. Use `innerForm` + puntas directo en GF. See [gf-direct-extension.md](gf-direct-extension.md) |
| Tags/classes as props or global mutable objects | Tags/classes in `data()` | Props dinámicos + defaultTagMap mutable = sobreingeniería. Cada componente sabe sus tags, los pone en data. Front overridea en su propio data. Sin Object.assign a objetos globales |
| `resolveTags("buttonTag")` with full suffix | `resolveTags("button")` | resolveTags agrega "Tag" automáticamente. Pasar sufijo = redundancia |
| `resolveComp(tag)` as global function | `this.resolveComp(tag)` as method | resolveComp registrado como method en pack. Usar via `this` — sin `/*global*/` |
| `mode` as prop from parent | `mode` in `data()` | Components know what they are. GI: "input", GF: "form", GF children: "input". No external override needed |
| `Object.assign(defaultTagMap, {...})` in front | Override tags in front's `data()` | Global mutation = side effects. Data override = clean, per-instance, cascade-friendly |
| DC renders same component twice via renderInput | DC as independent instance via `resolveComp` | Shared localInput = shared buttonRight = shared state. Independent instance = own localInput, own toggle |
| `$http` as `method: true` in pack | `$http` as `inner: true` in pack | `method` bindea con `.bind(vm)` → pierde propiedades (.get, .post). `inner` asigna a prototype directo |
| `Object.values(v)` in emitter for arrays | Sort by numeric ID from key name | Object key order is NOT source of truth. After delete+re-insert, order changes. Always: `Object.entries(v).sort(([a],[b]) => Number(a.split("_").reverse()[0]) - Number(b.split("_").reverse()[0])).map(([,v]) => v)` |
| `this.validateSelfValue` in dynamic GF created | `this.externalValue` | GF created wipes validateSelfValue via calculatedValue from empty localForm. externalValue always recalculates from prop via initVal |
| renderInput wrapper manual in each GF front | Let GF core handle it | GF renderInput auto-wraps with is-valid/is-invalid when mode=input. No need for manual wrapper in TF, ArrayAdd, ArrayForm fronts |
| `mode === "form"` check in GI renderInput | Move to GF renderInput | GI never has mode="form". Only GF knows about modes. GI renderInput is noop → defaultRenderInput |
| Missing `key` on components in v-for/map | Always `key={input.name}` | Without key, Vue recycles by position → state crossover on delete. Critical for SubdocRows in ArrayForm |
| `$refs.inputs` iteration for ordered validation | Iterate `localForm` + find ref by name | `$refs` have no guaranteed order. localForm preserves insertion order. Find ref by `localInput.name` match |
| Implementing everything at once | Build layer by layer, test each | Complex components (ArrayForm): structure first → data flow → interaction → validation. Each layer tested before next |
| GroupWrapperTag in `components: {}` | `this.GroupWrapperTag = X` in `created()` | JSX ignora `components` — siempre usa la variable JS del módulo. Override via created (no reactivo) |
| `innerGroupTag` in data | `useGroupWrapper` (bool) + `GroupWrapperTag` en created | innerGroupTag eliminado. Bool controla si wrappear, created define el tag |
| Two `created()` in same object literal | Single `created()` with all logic | JS silently drops first key. No error, no warning. ESLint `no-dupe-keys` detecta |
| Front GI replaces noop (`getInputProps`) | Front GI overloads default (`defaultGetInputProps`) | Replacing the noop breaks the chain — any component overriding it skips the front GI layer. Overload the default by calling `CoreGI.methods.defaultGetInputProps.call(this, displayVar)` and extending the result. Components call `this.defaultGetInputProps()` and get the front GI adaptations automatically |
| Emitter que nulifica como FILTRO (`if (!v.x) return null`) | Nulificar solo como transformación de tipo (`"" → null`) | **Distinción clave**: `"" → null` = normalización de tipo (OK, permite que validator evalúe required). `{measure:"hours", duration:null} → null` = filtro de validez (MAL, elimina valor parcial). Emitter TRANSFORMA tipos, NUNCA juzga validez. Validator REPORTA errores. Submitter DECIDE si envía. Bug real: TimeFrame emitter retornaba null si faltaba duration → form sin valor + sin errores + select mostrando 120 |
| Componente FW con `setup()` + `render()` Options API + loader (mixin) | Componentes que usan loaders quedan **Options API puros** | **SILENT REACTIVITY LOSS**: setup() corre PRE-mixin-merge. Vue 3 al detectar setup() asume Composition path → effect del render Options NO queda bindeado al mixin merged data. Síntoma: methods se ejecutan (counter incrementa en logs) pero render NO re-evalúa. Bug latente difícil de detectar porque NO hay error en consola. **Regla**: componentes con `$lodash`/`$urlSync`/`$emitter`/`$validateSelf`/etc → cero `setup()`. Si necesitas composition primitives, usa composable separado o el bridge regular-function (ver siguiente fila). |
| `setup() { return () => h(...) }` con `this.X` esperando reactividad | `setup() { return function () { return <div>{this.X}</div>; } }` (regular function, NO arrow) | **Bridge real para setup + loader**: arrow function = `this` lexical = `undefined` (setup no tiene this) → Vue no puede bindear → reactividad rota. Regular function = `this` dinámico → Vue invoca render con `this = instance proxy` → mixin merged data accesible reactivamente. Permite combinar setup() (composition primitives) con loaders (Options) sin romper nada. **No-arrow es la pieza crítica** que el 99% de devs no conoce. |
| `this.log.info("...")` en componente que cuelga de GI **sin** `debug: true` en data | `data() { return {debug: true, ...} }` durante desarrollo, remover para producción | **SILENT LOG LOSS**: GI define `log` computed como `Proxy(log.getLogger(...), {get: (target, prop) => (this.localDebug ? target[prop] : () => {})})`. Si `localDebug` es false, **toda llamada a `this.log.X` retorna funciones noop** — los logs se silencian sin error. `localDebug` lee en orden: `$options.$debug` → `data.debug` → `"debug" in $attrs` → `localConfig.debug`. Síntoma típico: pones `this.log.info("...")` para depurar un componente que cuelga de GI, no aparece nada en consola, asumes que el código no se ejecuta cuando en realidad sí se ejecuta — solo que `this.log` está silenciado. Confunde el diagnóstico. **Para depurar**: poner `debug: true` en `data()` durante el desarrollo. Para producción: removerlo o setear false. |
